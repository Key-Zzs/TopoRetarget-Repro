# Stage 9 — final constrained interaction-preserving refinement

Status: bounded RH/LH implementation with explicit assumptions.

## Scope and inputs

The acceptance window is `s7/cubemedium_inspect_1`, native frames `[0,60)`, using:

- canonical MediaPipe-21 source sequences;
- Stage 7 `toporetarget.warm_start.v1` artifacts;
- Stage 8 source interaction graphs and frozen weights;
- the Stage 6 cubemedium object mesh and 512-point robot collision-surface artifacts;
- the paper values in `configs/paper/retarget.yaml`.

The canonical source paths are the existing RH `..._rh_f000000_f000060_mp21.zarr`
and LH `grab/s7/cubemedium_inspect_1/semantic_left_f000000_f000060.zarr`. Input

is modified.

## Procedure

1. Load the sequence, warm start, graph, robot model, object mesh, and collision samples.
2. Cross-validate the solver-only convex-hull SDF against the Stage 6 reference SDF.
3. Build a deterministic full or adaptive QuerySet.
4. Solve Eq. (8)-(9) sequentially in local seed-delta coordinates with per-query slack.
5. Expand the adaptive set from the full-surface result and repeat until stable.
6. Recompute the final FK, interaction residual, bone residual, SDF, constraints, bounds,
   and provenance with independent reference queries.
7. Save one `toporetarget.final_retarget.v1` Zarr artifact and reports/visualizations in
   ignored `.local/` paths.

constraints, valid q bounds, deterministic QuerySet IDs, no independent hard-bound
violations, source/object/graph/warm-start hash integrity, artifact round-trip, and

same bounded frame range and comparing arrays and key metrics; wall-clock `solve_time_s`

## Stage 9.1 solver-robustness closeout

The v1 profile and its acceptance behavior are preserved. The independent v2
profile fixes the adaptive active-set continuation contract: after a solve, the
next initial vector contains the returned base/q coordinates, old slack remapped
by query ID, and minimum feasible slack for new IDs. The provenance records the
query order and whether `result.x` continuation was used. This does not change
Eq. (8), Eq. (9), paper weights, q/slack bounds, signed-distance sign, or the
full 512-point audit.

The strict termination contract stores optimizer convergence, status code,
message, `nit/nfev/njev`, objective and step diagnostics separately from
feasibility and audit checks. Status 9 is rejected even for a feasible
candidate. `feasible_stationary_v1` is explicitly deferred because no KKT or
projected-gradient proof is implemented. The fixed benchmark set, uniform
maxiter selection, repeat results, profile IDs, and profile hashes are recorded
in `.local/reports/stage9_1/maxiter_benchmark.json` and the corresponding
Stage 9.1 development-log entry. Optimizer and termination details remain
paper-undisclosed implementation assumptions.
